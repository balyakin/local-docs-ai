# 5. Ответ — это ещё не доказательство

Откройте `answer_question()` в `docqa.py`. Она берёт три найденных фрагмента, нумерует их `[1]`, `[2]`, `[3]` и передаёт вместе с вопросом в `/api/chat`. Инструкция просит модель отвечать только по этим кускам и прямо сказать, когда данных не хватает.

Попробуйте:

```bash
python docqa.py ask "Нужна ли бумажная квитанция для выдачи?"
```

В документе сказано: нужна цифра заказа, бумажная квитанция не обязательна. Ниже ответа CLI напечатает найденные фрагменты. Сверьте слова модели с файлом. Ссылки в её тексте полезны, но список источников приложение показывает отдельно: модель не управляет тем, какие файлы там будут названы.

**Попробуйте сами.** Задайте вопрос «Есть ли курьерская доставка?». В документах этого нет. Хороший ответ честно скажет, что сведений недостаточно. Если модель уверенно пообещает доставку, сохраните этот промах в свой список проверок. Маленькая модель может ошибаться даже при ясной инструкции.

Код также велит считать текст документов данными, а не командами. Это снижает риск, что случайная инструкция в файле собьёт ответ, но не делает систему непробиваемой. Поэтому приложение не выполняет действий из документов и не меняет их.

**Проверка:** у ответа есть фрагменты с путями и строками. На вопрос без факта в файлах вы не принимаете красивую догадку за правильный результат.
