# 7. Проверить, где программа врёт

Код может быть исправен, а ответ — плохим. У нас два этапа, и их полезно оценивать отдельно: нашёлся ли правильный фрагмент и сумела ли модель ответить по нему.

Сначала запустите автоматические проверки. Ollama для них не нужна:

```bash
python -m unittest discover -s tests -v
```

Тесты ловят ошибки чтения, границ фрагментов, запросов к локальному API, устаревшего индекса и показа источников. Они не ставят оценку качеству русского ответа. Для этого откройте [семь контрольных вопросов](../eval/questions.md) и спросите приложение вручную.

Запишите для каждого вопроса две отметки: **источник найден?** и **ответ верен?** У вопроса без ответа в документах верным считается отказ от выдумки. Если нужный кусок не попал в выдачу, меняйте поиск или разбиение. Если попал, а модель всё равно фантазирует, разбирайте запрос к `/api/chat` либо пробуйте более сильную локальную модель.

Теперь замените учебный пример своими файлами и составьте ещё семь вопросов: пять с ответом, два без. Попросите другого человека проверить приложение по ним. Никакого обещания «ИИ всегда знает» — только результаты, которые можно повторить.

**Готовность проекта:** человек с чистой установкой проходит `docs/ollama.md`, запускает приложение, задаёт вопрос по своим файлам и может открыть точный фрагмент, на который опирается ответ. Если он застрял, поправьте инструкцию. Если ответ неверен, оставьте этот вопрос в проверочном наборе. Так у репозитория появляется память об ошибках, а не только красивая главная страница.
