# 4. Найти нужный кусок

Теперь у нас есть вектор вопроса и векторы документов. `find_chunks()` считает косинусную близость между ними, сортирует фрагменты и берёт первые три. Для маленькой папки этого достаточно: отдельная векторная база здесь добавила бы установку и сложность, но не помогла бы понять сам поиск.

Проверьте его отдельно от языковой модели:

```bash
python docqa.py search "Когда можно забрать велосипед?"
```

Среди первых фрагментов должна быть часть `example.md` про выдачу. Посмотрите на путь и строки. Если вы добавили свои заметки в прошлой главе, результаты могут сдвинуться — это нормально. Важно, чтобы нужный кусок попал в показанный список.

**Попробуйте сами.** Спросите о диагностике тремя способами: «сколько стоит диагностика», «плата за осмотр» и «цена проверки велосипеда». Запишите, на каком вопросе нужная глава выпала из первых трёх результатов. Это полезнее, чем впечатление «поиск вроде работает».

Если фрагмент не найден, ответная модель его не восстановит. Сначала проверьте, что файл попал в индекс; затем — как он разделён на куски; только потом спорьте с формулировкой запроса. Такой порядок экономит время.

**Проверка:** `search` печатает исходные фрагменты без готового ответа. Вы видите, какие данные получит модель в следующей главе.
