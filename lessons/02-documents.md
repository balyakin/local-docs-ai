# 2. У текста должны быть адреса

Откройте `docqa.py` и найдите `scan_documents()`. Она обходит папку `documents/`, берёт только `.md` и `.txt`, читает UTF-8 и запоминает содержимое каждого файла. Заодно считает отпечаток всех документов. Поменяется хоть одно слово — отпечаток станет другим, даже если размер файла остался прежним.

Следом работает `split_document()`. Большой файл нельзя бездумно сунуть модели целиком: нужное место затеряется, а лимит контекста всё равно конечен. Функция режет текст на куски до 1000 символов. В Markdown новая глава с `#` начинает новый кусок. Для каждого куска остаются путь и номера строк.

Посмотрите на это без Ollama. Запустите `python` в папке проекта и введите:

```python
from pathlib import Path
from docqa import scan_documents, split_document

files, fingerprint = scan_documents(Path("documents"))
chunks = split_document(*files[0])
[(part["start_line"], part["end_line"]) for part in chunks]
```

Для исходного `example.md` получится четыре диапазона: `(1, 4)`, `(5, 8)`, `(9, 12)` и `(13, 15)`. Выйдите из Python командой `exit()`.

**Попробуйте сами.** Добавьте в `documents/` файл `my-notes.txt` с двумя короткими фактами о выдуманном мероприятии. Снова вызовите `scan_documents()` и убедитесь, что в списке появились два файла. Файл может лежать и в подпапке; путь к нему сохранится относительно `documents/`.

**Проверка:** каждый фрагмент имеет текст, имя файла и реальные номера строк. Эти поля понадобятся не только поиску. Именно по ним человек потом откроет источник ответа.
